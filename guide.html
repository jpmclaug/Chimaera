01 // System Architecture & Multi-Vendor Engines

[ SEC:ARCH ]

Chimaera is structured around a centralized Deal Engine that coordinates price polling, stock validation, and condition tracking across three distinct commercial endpoints:

Provider 01 REST API

Scryfall / TCGplayer

Queries Scryfall's authoritative catalog for card nomenclature, canonical image artwork URIs, collector metadata, and TCGplayer Market USD prices for Non-foil (usd), Foil (usd_foil), and Etched (usd_etched) variants.

• Lowest market price across all printings
• Automatic Direct TCGplayer product URLs
Provider 02 BinderPOS / JSON

Mighty Meeple Storefront

Interrogates MightyMeeple.com's live Shopify/BinderPOS inventory system (/search/suggest.json and /products/{handle}.js). Scans live stock availability and inspects condition tiers (Near Mint NM vs Lightly Played LP).

• Real-time in-stock vs out-of-stock check
• Direct 1-click cart checkout URLs
Provider 03 Finding API + Scraper

eBay Singles Market

Scans live eBay Buy-It-Now single listings. If official eBay Developer API keys (EBAY_APP_ID) are provided, it queries the Finding API; otherwise, it employs a resilient HTML scraping engine with price sanitization.

• Buy-It-Now filtered listings
• Outlier and junk lot filtering

04 // "Any Version" Intelligence vs Specific Printings

[ SEC:SCOPE ]
★ Any Version Mode (Default) RECOMMENDED FOR PLAYERS

When you track Any Version, Chimaera doesn't limit price checks to one printing. On every surveillance cycle, it evaluates all printings of the card across MTG history and extracts the absolute cheapest version available on the market.

  • Tracks lowest price across reprints, Masters sets, and Commander decks.
  • Respects your chosen finish (e.g. cheapest Foil across any set).
  • Stores set_code = NULL in the database to signify global edition monitoring.
Specific Printing Mode COLLECTOR SCOPE

When you select a specific set from the dropdown (e.g. MH3 #123, Alpha #45, Secret Lair Drop), Chimaera binds surveillance specifically to that exact printing, collector number, and Scryfall ID.

  • Ideal for tracking high-end Reserved List cards or specific artistic treatments.
  • Only polls stock and listings matching that specific set code.
  • You can simultaneously track both an "Any Version" and a specific collector edition of the same card!

08 // How to Get Prices to Update from the Site Itself

[ SEC:POLL-UI ]

Chimaera provides 5 distinct mechanisms to update prices directly from the web application interface without needing command-line tools or server restarts:

[ METHOD 1: TOP NAV WATCHLIST SWEEP ] Endpoint: POST /api/watchlist/refresh-all

"Poll Watchlist" Full Surveillance Button

In the top navigation bar, click the [ Poll Watchlist ] button.

  1. The navigation icon animates into a high-speed radar spin.
  2. A tactical toast alert notifies: [SYS:TELEMETRY] Executing price surveillance scan....
  3. The backend Deal Engine iterates over every card in your database, executing live queries across TCGplayer, Mighty Meeple, and eBay.
  4. Database price snapshots and timestamps are updated, active deals trigger Discord notifications, and the page automatically reloads with live prices.
[ METHOD 2: SINGLE TARGET CARD ] Endpoint: POST /api/watchlist/refresh/<id>

Individual Card "Poll" Action

In the Registry or Deals view, each card has a dedicated [ Poll ] button in its bottom-left footer. Clicking this refreshes only that specific single card across all 3 providers without querying other cards, ideal for rapid spot-checks on high-priority targets.

[ METHOD 3: CADENCE MODAL ] Endpoint: POST /api/worker/trigger

Cadence Modal "⚡ Poll Now" Trigger

Click the [ Cadence ] button in the navigation header to open the Surveillance Protocol modal (CONFIG // 0x7E). Click [ ⚡ Poll Now ]. This immediately runs a manual sweep and sets the database flag manual_poll_requested=true so any running worker processes synchronize immediately.

[ METHOD 4: AUTOMATED CADENCE ] Endpoint: POST /api/settings/cadence

Configuring Automated Polling Cadence in UI

Inside the Cadence modal, select an interval: Every 15 min (0.25h), 30 min (0.5h), 1h, 2h, 4h, 6h (Default), 12h, or 24h. Check "Enable Automated Background Surveillance" and click [ Save Cadence ]. This setting is stored in the database (SystemSetting). The standalone worker daemon (worker.py) checks this interval every 5 seconds and automatically reschedules without needing a restart!

[ METHOD 5: TARGET ACQUISITION ] Endpoint: POST /api/watchlist/add

Automatic Initial Scan on Card Registration

Whenever a new card is added via "Acquire Target", the backend automatically executes an initial price scan before saving and returning response data, guaranteeing newly tracked cards display live market prices immediately.

09 // How to Get Prices to Update from GitHub Actions

[ SEC:ACTIONS ]

Chimaera features complete, turnkey integration with GitHub Actions. An ephemeral Ubuntu runner spins up in GitHub's cloud, connects securely to your Neon PostgreSQL database, polls TCGplayer, Mighty Meeple, and eBay, updates the database, sends Discord deal alerts, and shuts down cleanly — at zero hosting cost and without running a local computer.

// GITHUB ACTIONS WORKFLOW EXECUTION TOPOLOGY
[ GitHub Cron Schedule / Manual workflow_dispatch ]
  ↓
[ Spins up Ubuntu Runner & Installs Python 3.11 + dependencies ]
  ↓
[ Injects ${{ secrets.DATABASE_URL }} & ${{ secrets.DISCORD_WEBHOOK_URL }} ]
  ↓
[ Executes: `python worker.py --once` ]
  ↓
[ Updates Neon Postgres DB & Emits Rich Discord Webhook Deal Alerts ]
  ↓
[ Runner Terminates Cleanly (0 Remaining Infrastructure Overhead) ]
CRITICAL STEP 1

Configure GitHub Repository Secrets

For the GitHub Actions cloud worker to access your cloud database and dispatch alerts, you must register your environment secrets in GitHub:

  1. Navigate to your GitHub repository in your web browser: https://github.com/<your-user>/<your-repo>
  2. Click on the Settings tab in the top repository menu.
  3. In the left sidebar, expand Secrets and variables and click Actions.
  4. Click the green "New repository secret" button.
Secret Name Requirement Description & Format
DATABASE_URL REQUIRED Your Neon Serverless Postgres URI:
postgresql://neondb_owner:npg_xxx@ep-xyz.us-east-2.aws.neon.tech/neondb?sslmode=require
DISCORD_WEBHOOK_URL RECOMMENDED Discord channel webhook for deal notifications:
https://discord.com/api/webhooks/123456789/abcdef...
EBAY_APP_ID OPTIONAL eBay Developer Finding API App ID (fallback scraper used if omitted)
AUTOMATED CRON

Automated Scheduled Sweeps (Default: Every 6 Hours)

The workflow file (.github/workflows/surveillance_worker.yml) runs automatically on a scheduled cron cadence:

on:
  schedule:
    # Runs every 6 hours at 03:00, 09:00, 15:00, 21:00 UTC
    - cron: '0 3,9,15,21 * * *'
  workflow_dispatch: # Allows manual trigger from GitHub Actions tab

You can modify the cron expression in this YAML file to any cadence (e.g. '0 */2 * * *' for every 2 hours, or '0 12 * * *' for daily at noon).

MANUAL UI TRIGGER

Trigger Price Update via GitHub Web UI (`workflow_dispatch`)

You can trigger a cloud price scan on-demand anytime from your phone, laptop, or browser without running any code locally:

  1. Navigate to your repository on GitHub.
  2. Click the Actions tab in the top navigation bar.
  3. In the left sidebar under "Workflows", click Chimaera Market Surveillance Worker.
  4. Look for the banner on the right: click the "Run workflow" dropdown button.
  5. Leave branch as main and click the green "Run workflow" button.
  6. A new job will appear in seconds. Click it to view live execution logs and see every card price polled and deal detected in real-time!
TERMINAL / CLI TRIGGER

Trigger Price Update via GitHub CLI (`gh`)

If you have the official GitHub CLI installed (gh), execute this single command from any terminal:

gh workflow run surveillance_worker.yml

10 // Standalone Worker Daemon & Local CLI (`worker.py`)

[ SEC:WORKER ]

In addition to GitHub Actions, you can run the standalone Python worker (worker.py) on your local machine, a VPS, or a Docker container:

// DAEMON MODE (CONTINUOUS SURVEILLANCE)
python worker.py

Keeps running indefinitely, updates the database heartbeat (worker_status = online), and dynamically adopts cadence updates from the UI.

Windows helper scripts: .\start_worker.ps1 or start_worker.bat
// SINGLE SWEEP CRON MODE
python worker.py --once

Scans all targets once, writes new prices, emits Discord alerts, and terminates with returncode 0.

// Available Worker CLI Arguments
--once : Run 1 scan sweep and exit immediately (Serverless/Cron mode).
--interval <hours> : Override DB polling interval (e.g. --interval 2.0).
--no-notify : Disables Discord deal webhook dispatches during poll.
--verbose : Enables detailed debug logging for network requests.

12 // Tactical Diagnostics & Troubleshooting Playbook

[ SEC:DIAG ]
// 1. Neon PostgreSQL Connection Pooling & Auto-Suspend

Neon serverless databases enter sleep state after periods of inactivity. Chimaera is pre-configured with pool_pre_ping=True and pool_recycle=300 in SQLAlchemy. This automatically checks the connection health and safely wakes up the Neon endpoint without throwing 500 errors or dropped socket exceptions.

// 2. Discord Webhooks Not Firing

Verify that DISCORD_WEBHOOK_URL is properly formatted and added to both your local .env and your GitHub repository Secrets.

// 3. Scryfall Autocomplete Delays or 429 Errors

Chimaera debounces Scryfall autocomplete queries by 250ms on the client and throttles provider requests to comply with Scryfall's rate-limit requirements (50–100ms per request).

// 4. Port Conflict on Windows (Port 5050 Occupied)

If a previous session did not release port 5050, run .\stop_app.ps1 or stop.bat in PowerShell / Command Prompt to gracefully terminate any stray processes and free the network port.
